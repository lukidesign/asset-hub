# Vigour Asset Hub 功能与交互审查

日期：2026-10-10。范围：当前本地原型，只读检查，不修改产品代码、配置或业务数据。

## 结论

页面架构已经基本齐全，但“发现资产 → 查看 → 导入 → 加入项目 → 协作治理”还没有形成可靠闭环。主要问题不是视觉，而是入口指向错误、成功提示没有实际结果、模型工具与真实场景脱节、各模块状态不一致。

发现 15 组问题：6 组 P1（优先修复核心流程），9 组 P2（后续完善一致性与体验）。这里的优先级针对原型评审，不代表已经发生生产安全事故。

## 环境、方法与边界

- 地址：`http://127.0.0.1:5173/`，macOS / Codex 内置浏览器，桌面视口。使用独立临时标签页，避免干扰用户现有状态。
- 优先尝试 Browser Use；连接响应异常后，使用内置浏览器进行 DOM、截图及只读交互检查。
- 交叉检查 `src/App.jsx` 当前实现；未通过提交表单、创建资产、删除、邀请、外部授权或改变成员权限来复现写操作。此类发现标为“代码确认”，与“实测”分开。
- 本轮使用 Product Design audit 的任务路径审查方法：先检查用户目标能否完成，再检查反馈是否真实，不把未接生产后端本身列为缺陷。
- 浏览器查看范围内未捕获 console error；这不证明所有路径没有错误。
- `npm run test:sites`：4 项通过、0 项失败；覆盖静态资源、应用回退、API/写请求隔离和交付文件，不等同于业务 E2E 通过。
- 独立终端 HTTP 检查无法连接本机端口，未取得完整网络请求/状态码证据；浏览器页面和本地 GLB 可正常加载。未进行生产接口、真实权限、真实 MCP、外部链接可用性或负载测试。
- 未测量真实 FPS、GPU 占用或加载耗时分位数；性能部分只列实现风险。

## 任务路径健康度

1. **首页 → 工作台：基本通畅。** 主入口可进入相应模块；首页是介绍，工作台是日常任务入口，保留两者合理。
2. **搜索 → 资产库：需改进。** 资产库内关键词能过滤；在其他模块输入后回车没有结果反馈。
3. **资产库 → 详情：部分通畅。** 非 3D 资产保留各自身份，inverter GLB 能实际渲染；排序和深度检查工具存在问题。
4. **导入 → 入库：高风险。** 界面完整，但文件/外链/图片关联、补图和规则执行不完整。
5. **工作台 → 项目 → 资产详情：阻断。** 项目错位，打开详情没有真实跳转。
6. **项目 → 成员/权限：需隔离和统一状态。** 不能把当前本地模拟当作生产权限系统；原型内部也有跨项目状态混用。
7. **文档 / MCP：展示可用、能力边界待加强。** 文档是目录级内容；MCP 是本地模拟，不应以页面“已连接”推断真实接入。

## 问题清单

### 01 · P1 · 工作台项目入口进入了错误项目【实测 + 代码确认】

- 位置：工作台 → 项目入口。
- 复现：点击“新能源座舱 HMI”。
- 期望：项目页选中新能源项目。
- 实际：进入“智能制造设备系列”。`initialProject` 只用于初始状态，后续点击没有同步项目选择。
- 影响：用户可能在错误项目上下文继续操作。
- 建议：按稳定项目 ID 导航，页面标题、选中状态、资产清单同时更新。
- 证据：`src/App.jsx:680`、`src/App.jsx:748`；截图 06。

### 02 · P1 · 多处操作只有成功提示，没有结果【打开详情实测；其余代码确认】

- 复现：项目资产点 inverter → 弹窗点“打开详情”。
- 期望：进入 inverter 的完整详情。
- 实际：弹窗关闭，仍在项目页，却提示“已打开…详情（原型）”。
- 同类：批量“加入项目”“添加标签”、创建集合、部分“查看报告”和历史版本预览，只触发提示，没有对应数据更新、内容或页面。
- 影响：用户无法判断完成与否；原型评审会误以为路径已闭合。
- 建议：已做的功能必须有可见结果；未做的功能禁用并标注“演示/暂未支持”，不要提示已完成。
- 证据：`src/App.jsx:374`、`src/App.jsx:376`、`src/App.jsx:704`；截图 07。

### 03 · P1 · 通用导入没有保留可用的文件、外链与展示图关联【代码确认】

- 检查路径：本地文件/链接 → 队列 → 完成并登记。
- 期望：入库后能打开原链接、预览模型，显示用户选定封面。
- 实际：本地队列只记录文件名等信息；登记记录没有保留原始 File、模型 URL 或外链 URL。图片主要只记录名称，并可能替换为通用图片。已手工登记的 inverter 等资产不受此描述影响。
- 影响：新导入资产看似存在，但无法继续复用源内容。
- 建议：即使只做会话原型，也保留源引用、展示图引用和导入元数据；刷新失效则明确提醒，不必因此扩展到生产存储。
- 证据：`src/App.jsx:582`–`585`。

### 04 · P1 · “待补展示图”没有可完成的补救路径【界面观察 + 代码确认】

- 复现路径：资产先进入队列且未提供展示图，例如预置 `material_pack.zip`。
- 期望：该任务上有“补充展示图”，补完后可登记。
- 实际：任务只有完成/暂停入口；上方选择图片只影响后续新任务，不回填已有任务；登记逻辑又会拦截缺图任务。
- 影响：用户被卡住，只能重新走一遍导入；同时没有单项移除入口。
- 建议：给每条任务增加补图、编辑、重试/移除入口，保留已填写的信息。
- 证据：`src/App.jsx:582`–`587`；截图 08。未执行实际上传。

### 05 · P1 · 成员角色没有按项目隔离【代码确认，未操作权限】

- 检查路径：项目 A → 成员角色 → 切换项目 B。
- 期望：同一成员在不同项目可以有不同角色。
- 实际：成员列表固定，角色状态仅以成员姓名为键，成员组件未接收项目标识。另有“默认访问范围”表单，但保存逻辑不保存该值。
- 影响：原型呈现的项目权限边界不可信。这是本地状态问题，不代表真实账号权限已改变。
- 建议：以 `projectId + memberId` 管理成员角色；访问范围保存并可读回；自定义角色应能被成员分配。
- 证据：`src/App.jsx:643`–`650`、`src/App.jsx:697`–`703`。

### 06 · P1 · 真实 GLB 的结构工具与场景没有联动【实测 + 代码确认】

- 复现：先打开泵详情，再打开 inverter → 结构 → 输入“不存在的节点” → 选择本体节点。
- 期望：搜索返回空结果；选中定位/高亮，显隐控制真实模型。
- 实际：搜索后仍列出全部 3 个节点；点击只改变右侧选择文字，场景不定位。显隐状态未传入 Three.js 场景；跨资产后眼睛图标还会显示隐藏状态，而模型仍可见。
- 建议：从真实场景生成结构树并双向绑定；切换资产重置节点、贴图和显隐状态；未接通前隐藏相关工具。
- 证据：`src/App.jsx:376`–`390`、`src/App.jsx:478`–`493`；截图 10、11。

### 07 · P2 · 顶栏搜索不是真正的全局搜索【实测 + 代码确认】

- 复现：工作台输入 `inverter` 并回车。
- 期望：展示结果面板或进入资产库结果页。
- 实际：工作台没有变化；手动点击资产库后才看到过滤结果。显示的 `⌘ K` 也没有对应快捷键处理。
- 建议：回车进入搜索结果；支持清除、无结果反馈和快捷键；明确搜索资产名称/ID/标签等范围。
- 证据：`src/App.jsx:195`–`214`、`src/App.jsx:344`–`366`；截图 02 为进入资产库后的结果。

### 08 · P2 · 排序与文字含义不符【实测 + 代码确认】

- 复现：资产库选择“最近更新”；再选择“文件从大到小”。
- 期望：时间倒序；统一文件体积单位后降序。
- 实际：默认最近更新保留原数组顺序，10 月 10 日资产排在旧资产后；大小排序把 177 KB 排在 42.1 MB 前。
- 建议：分别保存可排序时间戳与字节数；“链接/展示图”没有大小的记录统一置后。
- 证据：`src/App.jsx:366`；截图 03。

### 09 · P2 · 全局、项目和列表统计口径不统一【实测 + 代码确认】

- 复现：对照资产库分类、项目页顶部 KPI、项目资产/成员标签。
- 实际：资产库共 13 项、待评审 0；顶部却显示 52 项、7 个活跃项目、9 个评审；智能制造项目显示 15 项资产，当前清单 9 项。后两项虽标了“全量/当前清单”，但没有明确演示全集或差额依据。
- 期望：来自同一份数据，或清楚解释全量、可见、演示值的范围。
- 建议：计数统一计算；无法计算的储存容量等明确标注“演示数据”。通知中的待处理数量也应与列表一致。
- 证据：`StatStrip`、`ProjectAssetPanel`、`ProjectMembersPanel`；截图 06 与资产库实测数量。

### 10 · P2 · 项目信息在模块之间不能保持一致【代码确认】

- 检查路径：新建/重命名项目 → 工作台、导入目标、资产归属。
- 实际：项目管理内部维护自己的项目列表，工作台与上传仍使用固定列表；新项目默认资产清单回退为前 4 个样例资产；导入资产按项目名称匹配，重命名可能导致关联记录不可见。
- 建议：共用项目数据，以不可变 ID 关联资产、成员与权限；新项目初始为空，不套用样例清单。
- 证据：`src/App.jsx:603`–`609`、`src/App.jsx:680`–`699`、上传目标项目选项。

### 11 · P2 · 图片预览和真实三维能力混用【实测 + 代码确认】

- 复现：打开工作台推荐的工业离心泵，再对照 inverter。
- 实际：泵使用图片，却显示“3D 实时预览 · 可交互”及视角、测量等工具；inverter 则确实加载本地 GLB。
- 影响：用户难以区分展示图、模拟交互与真实可检验的模型。
- 建议：按资产能力展示“图片预览 / 真实 3D”；图片只提供适用操作。模型检查通过、测量、历史版本等也应基于真实数据或清楚注明模拟。
- 证据：`ModelDetail3d`、`LocalGlbViewer`；截图 05 与 10。

### 12 · P2 · 分享不能稳定返回指定资产【代码确认】

- 检查路径：详情“分享” / 列表“复制资产链接”。
- 期望：拿到可打开的资产页面 URL。
- 实际：详情复制的是资产 ID 与版本字符串，列表复制 `asset-hub://…`；当前应用没有相应资产路由解析。普通模块切换也不写入浏览历史。
- 建议：支持稳定的资产/项目地址，接通刷新、直接访问、前进后退；在接通前将按钮准确命名为“复制资产标识”。
- 证据：`src/App.jsx:297`、`src/App.jsx:553`、`App` 视图状态。

### 13 · P2 · 导入分类和规则过度简化，容易误导【代码确认】

- 检查路径：不同文件/链接类型、冲突处理、安全检查。
- 实际：ZIP 一律成为 Skill 卡，PNG 和多数云盘链接会落入 3D 模型；“创建新版本/跳过重复”未参与登记判断；安全检查和元数据开关没有业务处理。
- 建议：文件格式与资产业务分类分开；允许人工确认类型；冲突规则要有结果预览。未实现的校验标为未执行，不能仅凭 HTTP 前缀提示链接已验证可用。
- 证据：`src/App.jsx:583`–`587`。

### 14 · P2 · 文档目前是规范目录，还不是可用规范【实测 + 代码确认】

- 复现：打开文档，查看色彩、排版、Button、Table 等条目。
- 期望：能查看实际色值、字号、间距、状态、使用场景、组件示例和开发用法。
- 实际：主要是标题和一行说明，条目没有进一步内容；卡片箭头又容易暗示可打开。
- 建议：先补色彩/排版/布局 Token，以及 Button、Input、Table、Modal、Asset Card 的实际状态示例；明确它是项目自定义组件而不是已使用 Ant Design。
- 证据：`Docs`；截图 09。当前“未直接引入 Ant Design”的说明是准确且值得保留的。

### 15 · P2 · “待我评审”还不是个人可执行任务【代码确认】

- 检查路径：资产库“待我评审”、项目待评审统计、完成后提交评审。
- 实际：“待我评审”仅按资产成熟度为待评审过滤，没有评审人归属；没有完整的意见、通过/退回、处理记录闭环。
- 建议：区分“资产成熟度”和“评审任务状态”；要么先改成“待评审资产”，要么补本地评审人、意见与状态流转。
- 证据：`Library` 的 review scope、上传 `submitReview` 逻辑、项目评审 KPI。

## 补充风险与不应误判的事项

- **性能风险（静态发现）**：三维详情隐藏后仍保持挂载，渲染循环未按可见性暂停；清理未遍历释放模型几何/材质/贴图。建议增加可见性暂停、按需渲染和资源释放后，再测长时间使用及反复切换资产的内存/GPU 开销。不能从这些代码直接断言“已经卡顿”。
- **键盘与辅助技术**：部分弹窗没有 dialog 语义/焦点管理，MCP 客户端用可点击 article。建议专项键盘测试；本次不是完整无障碍合规审计。
- **本地模拟边界**：未接数据库、真实权限、真实 MCP、刷新后不保留会话数据，是当前约定，不直接作为缺陷；但必须在操作当下准确提示，而非只在文档底部说明。
- **当前顶栏布局**：上传图标、MCP 图标和头像内的项目入口是已确认方向，本次不建议无依据恢复旧导航。
- **视觉风格**：浅色工作区与深色模型预览的分工合理；当前优先事项是修通行为，不需要先整体重做视觉。

## 修复顺序建议

1. 第一批：01 项目跳转、02 真实结果反馈、03–04 导入引用与补图、05 项目角色隔离、06 模型结构联动。
2. 第二批：07 搜索、08 排序、09–10 数据统一、12 分享/路由、13 类型与导入规则。
3. 第三批：11 能力标识、14 文档示例、15 评审闭环，再做键盘可用性与性能专项。

验收应走完整任务：搜索一个真实模型 → 打开详情 → 返回原结果 → 放入指定项目 → 从该项目重新打开；另走导入文件/链接 → 补图 → 登记 → 找到源内容。仅有 toast、按钮高亮或静态计数不能算完成。
